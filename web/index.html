직선에서 루프로

전통 SDLC는 역할마다 단계를 나눠 갖고 문서·티켓·사인오프로 일을 넘깁니다. AI-native SDLC에서는 같은 여섯 단계가 Claude를 중심으로 도는 루프가 되고, 한 단계가 커밋한 아티팩트가 다음 단계를 깨웁니다. 사람은 루프 위에서 발의하고, 지시하고, 통제합니다.

전통 SDLC · 선형
  • PM → 아키텍트PRD 문서와 사인오프 회의
  • 아키텍트 → 엔지니어설계서를 해석해 티켓으로 쪼갬
  • 엔지니어 → QA단계 경계의 품질 게이트, 결함 티켓
  • QA → 릴리스주간 변경관리위원회(CAB)
  • 운영 → PM버그 리포트가 다음 분기 백로그로

      Get started

      첫 작업을 루프에 태우기

      Python 3.11과 git만 있으면 됩니다. 외부 패키지는 쓰지 않습니다. 에이전트는 submit까지만 하고, approve는 사람이 합니다.

      1. 의도를 적는다근거(티켓·지표·인시던트)가 붙은 intent.md 초안
      2. 게이트를 통과시킨다제품 오너가 수락해야 명세가 시작됩니다
      3. 계획이 승인된 뒤에만 코드를 쓴다CI의 plan-gate가 강제합니다
      4. 수락 기준을 테스트에 묶는다W-0142:AC-1 태그로 추적
      ~/your-repo
      # Plan — 의도를 캡처한다
$ python3 -m sdlc new "Checkout latency for EU users" --tier T2
work/2026/W-0142-checkout-latency-for-eu-users/intent.md
$ python3 -m sdlc submit W-0142 --stage intent

# 사람의 게이트 — 제품 오너
$ python3 -m sdlc approve W-0142 --stage intent --role product-owner

# Design → Build(plan mode)
$ python3 -m sdlc stage W-0142 spec
$ python3 -m sdlc stage W-0142 plan

# Test / Deploy — CI가 돌리는 것과 같은 게이트
$ python3 -m sdlc risk --base origin/main
$ python3 -m sdlc plan-gate --base origin/main --refs "$(git branch --show-current)"
$ python3 -m sdlc trace W-0142 --strict
